# 全版本 UDP 联机适配说明

本服务原先只对 **0.22.0** 验证过。本次把 `E:\Sky` 下**每个 APK 的
`lib/arm64-v8a/libBootloader.so`** 逐个解出、统计 UDP 协议字符串标志位
(`D:\工具\其他\ai\udp_apk_scan\apk_proto_scan.py`), 覆盖 **74 个版本 (0.6.5 .. 0.34.3)**,
据此加入"版本适配层"。

## 1. 三族划分(实测)

| 族 | 版本区间 | 特征 | C->S 包头 |
|----|----------|------|-----------|
| `legacy` | 0.6.5 .. 0.12.3 | 无 WebSocket / MQTT | `id:u8 + seq:u8`(2 字节) |
| `mqtt`   | 0.13.4 .. 0.21.5 | 带 MQTT(`/account/ws`) | 出现 6 字节 token 包头 |
| `modern` | 0.22.0 .. 0.34.3 | MQTT 移除 | `token:u32 + id:u8 + seq:u8`(6 字节) |

> 三族**共用同一套 PacketIds 与 GameMsgType 数值**(已与 0.12.1 / 0.22.0 真机抓包交叉验证:
> 0.12.1 同样发 GameMsg type 3 / 11 / 14)。差异集中在包头布局、JoinGame/LevelUpdate 负载
> 布局、NetLevelData 封装、以及聊天等是否走 MQTT。

## 2. 新增/改动的文件

- `src/protocol/versionMatrix.js`  —— **自动生成**的版本矩阵(74 个版本 -> 族 / so 指纹)。
  由 `D:\工具\其他\ai\udp_apk_scan\build_version_matrix.py` 依据扫描结果生成, 勿手改。
- `src/protocol/VersionProfile.js` —— 适配层核心: 版本解析、族判定、各族的 UDP 策略、握手推断。
- `src/protocol/packets/GameMsgPacket.js` —— GameMsgType 扩到全版本枚举(2,3,4,7,8,9,10,11,12,
  14,15,16,17,19,20,21,22,24) + 转发/丢弃策略集合。
- `src/protocol/types/NetLevelDataMsg.js` —— 支持按族选择 level data 封装布局(`msg22` / `raw`)。
- `src/protocol/packets/JoinGamePacket.js` —— 尾部字段(levelData 之后)随版本增删, 改为**容错截断**
  而非抛错: 关键字段(uuid/netVersion/levelChangeCount/levelId)先解析, 尾部不可信就只截尾。
  这样 0.23~0.34 改了 JoinGame 尾部布局也能进房。
- `src/services/GameMessageService.js` / `JoinService.js` / `domain/Player.js` / `PlayerStore.js` /
  `session/RoomServer.js` / `config/behaviour.js` —— 接入族判定、日志、/health 暴露、运行时开关。

## 3. GameMsg 转发策略(全版本)

| 类型 | 值 | 处理 |
|------|----|------|
| NetRpc | 2 | 同关卡转发(带 sourcePlayer) |
| PlayerStateDelta | 3 | 解快照 -> 每人重打包 -> 转发 + 回 Ack |
| Critters | 4 | **同关卡原样转发** |
| Affinity | 7 | 同关卡原样转发(`relayEventGameMsg` 控制) |
| NetLevelDataElect | 8 | 转发 |
| NetLevelDataRevoke | 9 | 权威移交 + 重新选举 |
| NetLevelDataRevokeAck | 10 | 记录 |
| NetLevelData | 11 | 权威校验 + 不透明缓存/转发 |
| NetLevelDataHeartbeat | 12 | 首个入关者成为权威 |
| SnapshotAck | 14 | 推进发送窗口 |
| MusicSync | 15 | **同关卡原样转发** |
| Metrics | 16 | 只记录, 不转发 |
| NetLevelElectionNominee | 17 | 同关卡原样转发 |
| AudienceHint/SocialBroadcast/ConsensusVote/Chat/SpotlightReq | 19/20/21/22/24 | 同关卡原样转发(`relayEventGameMsg` 控制) |

## 4. 运行时开关(见 `src/config/behaviour.js`, 可 `POST /debug/behaviour` 热改)

- `ROOM_FORCE_PROFILE=legacy|mqtt|modern` —— 强制所有玩家按某族策略(真机对比用)。
- `ROOM_RELAY_EVENT_GAME_MSG=0` —— 关闭事件类 GameMsg(7/19~24)转发(怀疑老版本闪退时用)。
- `ROOM_ELECT` / `ROOM_ELECT_ON_JOIN` / `ROOM_ENTER_GAME_ON_JOIN` /
  `ROOM_OPAQUE_LEVEL_DATA` / `ROOM_CATCH_UP_LEVEL_DATA` —— 原有开关, 不变。

## 5. 观测

`GET /health` -> `room.versionProfiles` / `room.versionMatrix` / `room.playerFamilies`;
`GET /players` 每个玩家带 `protocolFamily` / `protocolProfile` / `protocolLabel` / `protocolSource`。
玩家入房日志带 `protocolFamily` / `headerLayout` / `tolerantJoin` / `joinTruncated`。

## 7. 已知限制

- `mqtt` 族的**聊天/社交**在部分功能上走 MQTT over WebSocket (`/account/ws`), UDP 侧无法覆盖;
  UDP 房间内的移动/快照/事件同步不受影响。
- 无法从 UDP 帧区分"具体版本号", 只能区分族; 若要精确到版本, 需要 HTTP/登录侧把 User-Agent
  版本透传给房间(当前 `resolveProfile` 已预留 `version` 入口)。
