## API 请求监控在端口顺延时错位（2026-11-25）

- 现场证据：8443 与 8444 同时监听，8444 的服务进程持有标题为 `请求监控面板 :8443` 的窗口。旧实现按期望端口命名，多个进程还会轮询同一唤起标记。
- 修复：API 选定端口后用该端口初始化监控窗口，管理面板按实际端口写入唤起标记。
- 验证：Python 语法静态检查已执行。重启后系统报告 8444 的监听进程持有标题为 `请求监控面板 :8444` 的窗口。该窗口原先隐藏，写入 8444 的唤起标记后确认标记被消费且窗口可见。运行日志中已有客户端业务请求，窗口列表是否显示请求待确认。
- 适用版本：当前 API 与面板需成对更新。跨版本应用前核对端口回报行及监控标记目录。

## UDP 联机监控连接失败（2026-11-25）

- 根因：三个房间的启动日志均显示 Node.js 导入 `zod` 失败。房间进程退出后，监控访问本机管理端口 8080 得到 WinError 10061。旧提示把连接失败误报成缺少 `/packets` 路由。
- 修复位置及方法：在 `services/room-service` 按现有锁文件执行 `npm ci`。在 `services/panel-service/admin_panel_client.py` 区分 HTTP 404、其他 HTTP 错误和连接失败，并添加独立的 UDP 重启按钮。
- 验证：依赖安装退出码为 0。用户重启房间后，确认 UDP 25565–25567 已绑定，管理端口 8080–8082 的 `GET /packets?limit=1` 均返回 HTTP 200。客户端联机未验证。
- 适用版本：当前 `panel-service` 与 `room-service` 源码快照，日志中的 Node.js 版本为 v24.22.1。其他版本复用前应检查管理 HTTP 端口、路由和依赖锁文件。
